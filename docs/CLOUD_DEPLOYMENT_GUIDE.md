# BARQ LINK — دليل النشر السحابي والتشغيل المستقل (Production Deployment Guide)

يقدم هذا الدليل المرجع التشغيلي الكامل لتحويل مشروع **BARQ LINK** إلى منظومة إنترنت أشياء (IoT) سحابية ومستقلة تماماً تعمل على الكهرباء دون الحاجة للاتصال بجهاز الحاسوب.

---

## 1. البنية التحتية والمنافذ التشغيلية (Architecture & Network Ports)

يعمل النظام على المنافذ الموحدة التالية:
- **منفذ TCP المودمات (Port 5050)**: خادم `RelayServer` المخصص لاستقبال اتصالات GPRS المباشرة من مودمات Quectel M25 وتنفيذ بروتوكول `BARQ-RELAY-v1`.
- **منفذ لوحة التحكم والـ REST API (Port 4000)**: خادم HTTP موحد يخدم كلاً من:
  - واجهة المستخدم التفاعلية (Web Dashboard) على المسار `/`
  - واجهات البرمجة `/api/health`, `/api/nodes`, `/api/relay/send`
  - ترقية اتصالات WebSocket الحية (WSS/WS) مباشرة على نفس المنفذ لضمان العمل السلس عبر أي Reverse Proxy سحابي.
- **منفذ WebSocket المساعد (Port 4001)**: مدعوم تلقائياً للتوافق مع الإصدارات السابقة.

## 2. خيارات الاستضافة السحابية المتاحة (Hosting Platforms)

### الخيار 1: خادم سحابي مستقل ودائم (Oracle Cloud Always Free VPS) — الحل المثالي الموصى به
يوفر حساب Oracle Cloud المجاني مدى الحياة (Always Free) خادماً افتراضياً (VM.Standard.A1.Flex حتى 4 أنوية و24GB RAM، أو VM.Standard.E2.1.Micro) بعنوان IPv4 عام ثابت ومنافذ مفتوحة بالكامل مجاناً للأبد.

#### خطوات التجهيز في Oracle Cloud (التدخل البشري الوحيد المطلوب):
1. سجل في [Oracle Cloud Free Tier](https://www.oracle.com/cloud/free/) واختر منطقتك الأقرب (مثل Frankfurt أو Jeddah).
2. أنشئ جهازاً افتراضياً بنظام **Ubuntu 22.04 LTS** أو **Ubuntu 24.04 LTS**.
3. في صفحة **Virtual Cloud Network (VCN)** -> **Security Lists** -> أضف **Ingress Rules** التالية:
   - **Port 5050 TCP** (Source CIDR: `0.0.0.0/0`)
   - **Port 4000 TCP** (Source CIDR: `0.0.0.0/0`)
   - **Port 80/443 TCP** (Source CIDR: `0.0.0.0/0`)
4. اتصل بالخادم عبر SSH ونفّذ السكربت المؤتمت بنقرة واحدة:
   ```bash
   bash scripts/deploy_vps.sh
   ```
5. سيعمل الخادم كخدمة `systemd` تعمل 24/7 وتعيد التشغيل تلقائياً عند أي إعادة تشغيل للخادم.

### الخيار 2: منصة الحاويات السحابية (Fly.io)
تم تجهيز ملفات `Dockerfile` و`fly.toml` في المجلد الرئيسي:
1. حمّل أداة `flyctl` وسجل حسابك: `fly auth signup`
2. داخل مجلد المشروع، نفّذ:
   ```bash
   fly launch --no-deploy
   fly deploy
   ```
يقوم `fly.toml` تلقائياً بتوجيه منفذ TCP 5050 لمودمات M25 ومنفذ HTTP 4000/443 للوحة التحكم.

## 3. إعداد القطع المادية للتشغيل المستقل (Hardware Setup & Power)

### متطلبات التغذية الكهربائية (Power Supply Requirements):
> ⚠️ **تحذير هندسي حاسم**: مودم Quectel M25 يستهلك ما يصل إلى **2 أمبير لحظياً** أثناء الإرسال اللاسلكي عبر موجات 2G GPRS.
- **تغذية الأردوينو**: محول جداري 9V إلى 12V DC على منفذ Barrel Jack أو 5V DC عبر كابل USB موصول بشاحن هاتف أصلي (وليس منفذ الحاسوب).
- **تغذية مودم Quectel M25**:
  - وحدة خفض جهد مستقلة (مثل LM2596 أو شاحن بطارية ليثيوم 1S 3.7V-4.2V) مضبوطة على **3.8V إلى 4.2V** بقدرة 2A.
  - **ممنوع بتاتاً** توصيل VCC الخاص بمودم M25 بمخرج 3.3V أو 5V الخاص بالأردوينو، لأن ذلك يسبب إعادة تشغيل فورية للمودم عند محاولة فتح مقبس TCP (Brown-out Reset).
  - **يجب ربط الأرضي (GND) مشتركاً** بين الأردوينو ومودم M25 ومصدر التغذية.

### التوصيلات السلكية (Wiring Matrix):
| دبوس الأردوينو (Arduino Uno) | توصيله مع Quectel M25 | الغرض |
| :--- | :--- | :--- |
| **Pin 2 (RX)** | **TXD** للمودم | استقبال بيانات واستجابات AT ومقبس TCP |
| **Pin 3 (TX)** | **RXD** للمودم عبر مجزئ جهد (1kΩ / 2kΩ) | إرسال أوامر AT وبيانات الحزم |
| **Pin 7 (OUT)** | ريلاي / ترانزستور / دخل لوجيك لـ PIC | تشغيل الحمل أو إرسال نبضة للـ PIC |
| **Pin 13 (LED)** | ليد مدمج على البوردة | وميض سريع = جاري الاتصال \| مضيء ثابت = متصل ومسجل |
| **GND** | **GND** للمودم ومصدر الطاقة | أرضي مشترك إلزامي |

## 4. رفع السوفتوير على القطعتين (Firmware Upload)

تم تجهيز ملفين مستقلين بالكامل داخل مجلد `firmware/`:

### للقطعة الأولى (Unit 1 — ALPHA):
- الملف: `firmware/BARQ_ALPHA_STANDALONE.ino`
- اسم المعرف في الشبكة: `ALPHA`
- منفذ الأردوينو في الفحص: `COM3`
- افتح الملف في Arduino IDE، اختر البوردة **Arduino Uno**، واختر المنفذ ثم اضغط **Upload**.

### للقطعة الثانية (Unit 2 — BRAVO):
- الملف: `firmware/BARQ_BRAVO_STANDALONE.ino`
- اسم المعرف في الشبكة: `BRAVO`
- منفذ الأردوينو في الفحص: `COM4`
- افتح الملف في Arduino IDE، اختر البوردة **Arduino Uno**، واختر المنفذ ثم اضغط **Upload**.

## 5. تسلسل التشغيل المستقل التلقائي (Autonomous Boot Flow)

عند توصيل الكهرباء لأي من الوحدتين دون ربطها بالحاسوب:
1. **0 ثوانٍ**: تشغيل اللوحة وبدء وميض الليد على Pin 13 كل 250 ميلي ثانية.
2. **3 ثوانٍ**: تهيئة مودم Quectel M25 وإلغاء الصدى (`ATE0`).
3. **6 ثوانٍ**: التأكد من وجود شريحة SIM والتحقق من حالتها (`AT+CPIN? -> READY`).
4. **9 ثوانٍ**: التسجيل على شبكة المحمول GSM (`AT+CREG? -> 0,1` أو `0,5`).
5. **12 ثانية**: إرفاق حزم بيانات GPRS (`AT+CGATT=1`).
6. **15 ثانية**: تفعيل سياق الـ PDP والحصول على IP من شركة الاتصالات (`AT+QIACT`).
7. **18 ثانية**: فتح مقبس TCP نحو الخادم السحابي (`AT+QIOPEN="TCP","172.104.241.168",41747`).
8. **20 ثانية**: إرسال مصافحة التسجيل:
   ```json
   {"type":"REGISTER","deviceId":"ALPHA","version":"BARQ-RELAY-v1"}
   ```
9. **21 ثانية**: استلام تأكيد التسجيل `REGISTER_ACK` من الخادم -> **يضيء ليد الحالة Pin 13 بشكل ثابت (Solid ON)** للدلالة على أن الوحدة أصبحت أونلاين سحابياً ومستعدة لاستقبال وإرسال الأوامر.
10. **كل 25 ثانية**: إرسال نبضة حياة `PING` للحفاظ على مقبس الشبكة مفتوحاً ومنع إغلاقه بواسطة جدار الحماية الخلوي (Carrier NAT Timeout).
11. **عند انقطاع الشبكة**: تدخل الوحدة تلقائياً في دورة استعادة تدريجية تغلق المقبس القديم وتعيد الاتصال دون الدخول في حلقات إعادة تشغيل عشوائية.

## 6. إرسال الأوامر والتحكم عبر لوحة الويب

افتح رابط لوحة التحكم من أي هاتف أو متصفح خارج الشبكة:
**`https://rvoje-213-6-167-221.run.pinggy-free.link`**

- ستظهر البطاقات الذكية لـ `ALPHA` و`BRAVO` وحالتهما الحقيقية (`ONLINE` / `STANDALONE_GPRS`).
- لإرسال أمر تشغيل ريلاي إلى BRAVO:
  - اختر المرسل: `ALPHA` أو لوحة التحكم.
  - اختر المستقبل: `BRAVO`.
  - اضغط إرسال.
  - ينقل الخادم السحابي الحزمة إلى مودم BRAVO عبر GPRS.
  - ينفذ BRAVO الأمر ويفعّل المخرج Pin 7 ويقوم تلقائياً بإرجاع تأكيد الاستلام `DELIVERY_ACK`.
  - تعرض لوحة الويب علامة النجاح وتاريخ وزمن الوصول بدقة الميلي ثانية (RTT).
